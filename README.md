# PGallery — общий сборщик галереи

Общий сборщик с локальным предпросмотром и подготовкой PR через GitHub Actions.
Настройка репозитория, токена и Pages: [PUBLISHING.md](PUBLISHING.md). Один Python/Jinja2-сборщик
используют CLI и dev-админка бота. Базовый дизайн — PT Sans / PT Sans Narrow,
горизонтальная лента, согласованные пропорции desktop/mobile. Выбранный в админке
шрифт применяется к карточке и странице выставки; общие табы остаются PT Sans Narrow.
Inter, Playfair Display, Montserrat, Merriweather и Roboto Mono включаются в сборку
локально (обычное и курсивное начертания с переменным весом), без внешнего CDN.
Georgia и system используют шрифты устройства. Финальный вариант
дизайна ещё не выбран; дополнительные стилевые варианты и зернистость пока не включены.

## Локальная админка

Соседние каталоги `pgallery_bot` и `web` должны лежать рядом. `compose.dev.yaml`
монтирует `web/src` только для review, только на чтение; флаг `REVIEW_GALLERY_PREVIEW=1`
включает новые маршруты. Production Compose этот флаг не включает. После правок Python-кода сборщика
перезапустите только review; изменения шаблонов/CSS подхватываются при следующей сборке.

В заявке нажмите **«Предпросмотр: компьютер»** или **«Предпросмотр: телефон»**.
Сначала сохраните текст, оформление и EXIF. Откроется новая вкладка с главной:
компьютер — вся область окна, телефон — 390×844 (или меньше, если окно меньше).
Меню «Предпросмотр» в углу позволяет вернуться к заявке, сменить устройство,
открыть историю и скачать ZIP. Старый генератор отдельных HTML остаётся отдельно
и доступен только после приёмки.

Главная предпросмотра содержит все пригодные принятые **локальные** заявки и
выбранную непринятую заявку, если строится её предпросмотр. Другие непринятые заявки
не включаются. Проверяемая выставка всегда стоит первой, включая уже принятую; остальные идут
по дате приёмки. Это порядок конкретного предпросмотра, даты в базе не меняются. Это ещё не список опубликованных выставок. В исходном проекте
порядок задаёт явный `content/catalog.json`; изменение существующей выставки его не меняет.

При смене таба надписи плавно меняют акцент, размер и положение; видимые карточки
каскадно уходят вниз и поднимаются для нового режима. Наведение поднимает карточку
на 12 px. При открытии выставки карточки уходят вниз, табы — влево, фон меняет цвет,
после чего появляется содержимое (450–650 мс). URL и Back работают, ссылки доступны без
JS. Для `prefers-reduced-motion` анимации отключены.
Лента прокручивается колёсиком, тачпадом, перетаскиванием мышью и обычным touch swipe.
После drag клик не открывает карточку. Угол и положение фото в стопке немного
различаются по стабильному хешу выставки: при повторной сборке ничего не прыгает.
При наведении фото увеличиваются на 5%.

Клик по фотографии открывает модальный просмотр: вписать в экран / масштаб 1–5×,
колесо, кнопки +/−, двойной клик, pinch двумя пальцами, перетаскивание увеличенного
изображения. Закрытие — кнопка или Escape; фокус возвращается к фотографии.
Используется существующая web-копия до 2560 px, приватный оригинал не раскрывается.

В админке у каждого фото есть отдельные EXIF-переключатели. Изначально они следуют
выбору автора; сохранённое решение администратора переопределяет видимость каждого
поля. Скрытые значения остаются в базе, но исключаются из публичного manifest и HTML.
Настройки `_visibility` хранятся в `exif_override_json`; миграция БД не нужна. Перемещение между страницами
не требует API: статический `views.js` содержит подготовленные фрагменты.

## Команды

Python 3.13+ (в боте — 3.14). Из каталога `web`:

```powershell
uv sync
uv run gallery import --project . --manifest C:/path/to/manifest.json
uv run gallery validate --project .
uv run gallery build --project . --output dist-review-1
uv run gallery serve --project . --output dist-review-2 --port 18100
```

Выходная папка должна быть пустой: сборщик не удаляет чужие файлы. `serve` слушает
только 127.0.0.1. Для остановки — Ctrl+C. Можно также использовать
`PYTHONPATH=src` и `python -m gallery_build`, если Jinja2 уже установлен.

ZIP из админки содержит `site/` (готовый сайт), `source/content/` (публичные исходные
данные) и `metadata.json` (ревизии). Для непринятой заявки ZIP также содержит приватные
уменьшенные фото в `site/media/` и `source/media/`; их нельзя публиковать до утверждения. После распаковки сборка исходников:

```powershell
uv run gallery validate --project C:/path/to/unpacked/source
uv run gallery serve --project C:/path/to/unpacked/source --output C:/path/to/new-preview
```

Для ручной правки измените manifest либо добавьте
`content/exhibitions/<id>/custom.css`. CSS действует только на странице выставки.
Повторный import обновляет manifest, сохраняет custom.css и прочие ручные файлы.
Режим произвольного custom.html/custom.js и обратная загрузка ZIP в админку пока не реализованы.

## Контракт manifest v1

Строгая проверка реализована в `src/gallery_build/builder.py`. Неизвестные поля
запрещены. Пример:

```json
{
  "schema_version": 1,
  "id": "exh-example",
  "kind": "author",
  "title": "Между делом",
  "author": "Автор",
  "description": "Лица, места и короткие остановки.",
  "date": "2026-11-14",
  "theme": {"background": "#fff4ed", "accent": "#15425d", "font": "pt_sans"},
  "photos": [{
    "id": "photo-1",
    "url": "https://media.example/web/photo.jpg",
    "preview": "https://media.example/previews/photo.jpg",
    "caption": "Тихая пауза",
    "alt": "Человек у окна",
    "width": 1200,
    "height": 800,
    "exif": {"camera": "X-M5", "focal_length": "21 mm", "iso": "640"}
  }]
}
```

`kind` поддерживает `author` и `collective`; приёмка пока создаёт только `author`.
EXIF: только camera/f_number/exposure_time/iso/focal_length. GPS, служебные комментарии,
Telegram ID и секреты в контракт не входят. URL только HTTP(S), без учётных данных,
query/подписей и fragment, либо строгий относительный путь `media/<id>/<photo>.jpg`
к файлу внутри сборки. CLI копирует `media/` вместе с сайтом. Адаптер берёт ссылки только из настроенных public web-копий S3.
Фон карточки и страницы берётся из одного поля, цвет текста — из выбранного accent.
Дата и EXIF приглушаются прозрачностью, выбранный цвет не подменяется автоматически.
Пользовательский текст экранируется, как HTML-шаблон он не исполняется.

## Версии, изоляция и ограничения первого этапа

- ZIP сохраняется в приватном generated-бакете, `generated/<submission-id>/preview/<hash>.zip`.
  Повтор той же сборки возвращает ту же версию. Изменение входных данных или сборщика
  создаёт другую. Сохранённые HTML/CSS/JS не меняются; админка отмечает устаревшую версию.
- Вход и CSRF-проверка общие с админкой. Preview iframe и HTTP CSP используют sandbox
  без `allow-same-origin`. Запрещены формы, top navigation и fetch. Шрифты встроены в CSS,
  чтобы работать с Basic Auth внутри sandbox. Работающий код не получает origin админки.
- **Фото уже принятых заявок не копируются в ZIP и пока не версионируются.** Снимок фиксирует их URL,
  но удаление/перезапись объекта меняет доступность старой версии. Принятые фото уже
  доступны в публичных S3-бакетах. Закрытые черновики и неизменяемые media keys — отдельный этап.
- Для выбранной непринятой заявки оригиналы читаются из приватного хранилища
  последовательно через временный файл; создаются JPEG до 2560 px без EXIF/XMP.
  Разрешённые EXIF-поля показываются отдельно по сохранённым данным и согласию автора.
  Копии лежат внутри защищённого ZIP и обслуживаются тем же авторизованным маршрутом.
  Ни приёмка, ни запись в публичные бакеты при этом не выполняются. Лимит оригинала
  100 МБ / 40 Мп, суммарных копий 18 МБ; общий лимит ZIP также применяется.
- Сборка выполняется в ограниченном синхронном задании через thread pool под существующим
  межпроцессным maintenance lock; запрос ждёт завершения. Очередь/worker пока не добавлены.
  Лимиты: 50 выставок, 100 фото на выставку, ZIP до 24 МБ. Это локальный первый этап.
- Общие фрагменты всех выставок загружаются одним views.js. Перед большим публичным
  каталогом нужны измерения и ленивое разбиение. История ZIP автоматически не очищается.
- PR-интеграция использует отдельный токен только для запуска Actions и чтения.
  Запись ветки/PR выполняется в Actions; Pages после merge включается переменной
  PAGES_ENABLED. Изменений VDS/NAS этот локальный этап не выполняет.

## Проверки

```powershell
uv run python -m unittest discover -s tests -v
```

Интеграционные тесты адаптера — `pgallery_bot/tests/test_gallery_preview.py`.
Они запускаются, когда оба checkout лежат рядом, и явно пропускаются в изолированном
checkout бота. Браузерная проверка проведена на локальной админке в Chrome:
HTTP Basic, sandbox, фото/шрифты, desktop 1440×900, mobile 390×844, переход и возврат.

Шрифты: [PT Sans](https://github.com/google/fonts/tree/main/ofl/ptsans) и
[PT Sans Narrow](https://github.com/google/fonts/tree/main/ofl/ptsansnarrow), лицензии
OFL лежат рядом с файлами. Дополнительные семейства и их OFL взяты из [Google Fonts](https://github.com/google/fonts/tree/main/ofl); файлы — `assets/fonts/`. SVG взяты из согласованного Figma-файла PGallery.
Экспорты макетов в `design-exports` и архив для оценки не входят в исходники сайта.
